# Changelog

All notable changes to this project are documented here. Format loosely follows [Keep a Changelog](https://keepachangelog.com/).

## [Unreleased] — 2026-09-22 — Readable forms and a contact inbox that cannot lose messages

### Fixed

- **Fixed: every form on the site rendered its text white on white.** `main` is a white content card (`public/styles.css`), but the form-control rule set `color: #fff` over a near-transparent background — styling written for the dark page background behind the card. Anything typed into the contact form was invisible, and so was the username field in the admin sign-in dialog (the password field escaped it only because `input[type="password"]` was missing from the selector list). Controls are now dark-on-white with readable placeholders, a legible Chrome autofill state, and coverage for every text-like input type. Verified by rendering the contact page and the sign-in dialog in headless Chrome before and after.
- **Fixed: the header nav drew list bullets between links** on every page — the `<ul>` had no list reset.
- **Fixed: the Snake page's controls tip was grey-on-grey.** It was styled for a dark surface while sitting on the white card.
- **Fixed a typo** in the Connect 4 project description ("transpositon" → "transposition").

### Added

- **Contact form submissions are now stored** in `data/messages.json` (`lib/messages.js`, atomic writes, newest first, capped at 1000). Previously a submission existed only as an outbound email: if SMTP was misconfigured, rate limited, or down, the message was gone with no record anywhere, and the static build — which has no `/api/contact` behind it at all — dropped every submission it received. The message is saved *before* the email is attempted, so delivery failure is now reported (`emailed: false`, flagged in the inbox) instead of losing what the visitor wrote.
- **Added an admin inbox** at `/admin/messages` plus `GET /api/admin/messages`, `PATCH /api/admin/messages/:id` (read/unread), and `DELETE /api/admin/messages/:id`. Gated behind two new capabilities, `contact.messages.read` and `contact.messages.manage`, granted to `owner` and `admin` only — contact messages are private, so `editor` and `author` do not get them. An **Inbox** link appears in the edit toolbar for anyone holding the read capability.
- **Added rate limiting to `POST /api/contact`** — 5 submissions per sender IP per 10 minutes, so a persisted inbox cannot be flooded.
- **Added a `mailto:` fallback to the contact form.** When the API is unreachable (the static build, or a server outage), the page now offers the visitor a prefilled email instead of only showing an error.
- **Added tests:** `tests/messages.unit.test.js` covers the store (persistence, reload, read/delete, failed-email recording), and the integration suite now asserts a submission survives an SMTP failure, that validation still rejects empty fields, and that visitors cannot read or change the inbox. The integration tests point SMTP at a closed port so `npm test` never sends real mail.

## [Unreleased] — 2026-07-21 — Site-wide audit: security, reliability, accessibility, CI

A full pass over the codebase covering security, functional correctness, engineering infrastructure, and UI accessibility. Every item below was verified empirically (automated tests, a live server hit with `curl`/Playwright, or a reproduced exploit payload) rather than assumed fixed from reading the diff.

### Security

- **Fixed: stored XSS on public project pages.** `routes/pages.js` passed a project's `image` field straight into the `project.html` template without `escapeHtml()` — every sibling field (`title`, `description`, `summary`, ...) was escaped except this one. A crafted `image` value like `/x.png" onerror="alert(document.cookie)" x="` broke out of the `<img src="...">` attribute and executed for every visitor to `/projects/:slug`. Reachable by the lowest-privilege CMS role (`author`).
- **Fixed: stored XSS → privilege escalation in the blog editor.** `routes/pages.js` serialized a post's fields with `JSON.stringify()` and embedded the result raw inside a **single-quoted** HTML attribute in `views/editor.html`. `JSON.stringify` escapes `"` but never `'`, so a post title containing `'` broke out of the attribute (`x' autofocus onfocus='...'`). Because the payload only fires when an `editor`/`admin`/`owner` opens the draft to review it, and the CSRF token sits in a plain, script-readable `<input>` on the same page, this was a path from the lowest-privilege author role to full site takeover (arbitrary write via `/api/admin/site-file`) via a reviewer's session. Fixed by escaping the serialized JSON before embedding it.
- **Fixed: CSS-injection / clickjacking-style overlay via rich-text posts.** `sanitizeRichHtml()` (`lib/data.js`) allowed the `style` attribute on every tag with no `allowedStyles` filter, so any content author could set `position:fixed` + full-viewport dimensions on a `<span>` in a published post and overlay arbitrary content on the page. Added an explicit `allowedStyles` allowlist (color, font-weight/style, text-align/decoration) — verified `position`/`z-index`/`width` are now stripped while safe properties survive.
- **Upgraded `nodemailer` 7 → 9**, patching 7 published CVEs including a HIGH-severity SMTP command injection and multiple CRLF header-injection issues. `npm audit` was 0 → 2 vulnerabilities (1 high, 1 moderate) → 0 after this and a `postcss` patch bump. Re-verified the contact form sends real email correctly post-upgrade (the core `createTransport`/`sendMail` API is unchanged across majors).
- **Added security response headers** to every response via the shared `send()` helper in `lib/http.js`: `Content-Security-Policy`, `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy`, `Permissions-Policy`, and `Strict-Transport-Security` on HTTPS. The CSP allowlist was tuned against the site's actual external dependencies (Google Fonts, Quill CDN, Google Analytics) and verified with a full Playwright pass across every page plus the authenticated editor page — zero CSP violations.

### Reliability

- **Fixed: `lib/data.js` silently 500'd every page when MongoDB was unreachable.** `loadPosts()` had no fallback if the Mongo query threw — now catches the error, logs a warning, and falls through to the JSON-file backend. Read paths degrade gracefully; write paths (`updatePosts()`) intentionally do **not** fall back, since silently diverging from Mongo on write would be worse than a loud failure.
- **Fixed: `public/challenges.js` had a JavaScript syntax error** (`total ?? document.querySelectorAll(...).length || 0` — mixing `??` and `||` without parentheses is illegal). This crashed parsing of the *entire file*, silently killing all interactivity on `/challenges` with zero console output pointing at the cause. Added a permanent regression test (`tests/public-scripts.unit.test.js`) that syntax-checks every file in `public/*.js` — this exact class of bug will now fail CI instead of shipping silently.
- **Fixed: orphaned temp files from a Windows file-lock race.** `writePostsAtomically()` wrote to a `.tmp-<pid>-<timestamp>` file then `rename()`d it; if the rename failed (found 22 stale copies accumulated in `data/`), the temp file was never cleaned up. Now catches a rename failure, deletes the temp file, and re-throws.
- **Fixed: `npm test` was silently depending on real production secrets.** `tests/server.integration.test.js` requires `../server`, which unconditionally runs `dotenv.config()` — so every local test run against a real `.env` tried to connect to the live MongoDB Atlas cluster and hung for the connection timeout. Now forces `MONGODB_URI=''` before the `require`, so tests exercise the file-storage code path deterministically, no network dependency.
- **Fixed: `npm test` recursed into a vendored directory.** An unrelated vendored source tree sat in the repo root; the old `node --test` invocation had no path filter and picked up its build scripts, reporting 5 false failures. Scoped the test script to `tests/**/*.test.js`.
- **Fixed a stale test assertion.** `tests/data.unit.test.js` expected `sanitizeRichHtml()` to rewrite a disallowed `href` to `"#"`; the sanitizer actually strips the attribute entirely, which is *safer* (no href at all vs. a clickable no-op), not a regression. Updated the assertion to match the real, safe behavior instead of loosening the check.
- **Removed a duplicate `content` object key** in `lib/data.js`'s `loadProjects()` (caught by the new ESLint pass, `no-dupe-keys`). The last-declared value was already the one taking effect at runtime (JS duplicate-key semantics: last wins, and it happened to be the sanitized one) — this was dead/confusing code, not a live bug, but removed for clarity.
- **Content:** archived a leftover published test post ("Untitled Post 1", slug `dynamo-paper`) that was live on the public `/blog` — flagged and confirmed with the site owner before touching it, rather than assumed safe to remove.

### Engineering infrastructure

- **Added CI** (`.github/workflows/ci.yml`): `npm ci` → `npm run lint` → `npm test` → `npm audit --audit-level=high` on every push/PR to `main`.
- **Added Dependabot** (`.github/dependabot.yml`): weekly automated PRs for npm and GitHub Actions dependency updates.
- **Added ESLint** (`eslint.config.js`, flat config, v9): separate rule sets for Node code (`lib/`, `routes/`, `server.js`, `tests/`) vs. browser code (`public/`), plus a dedicated globals list for the `flappy-bird-ai` p5.js sketch (a multi-file, no-modules browser script where cross-file top-level variables legitimately look like undefined/redeclared globals to a per-file linter). Fixed everything down to 0 errors (27 pre-existing unused-variable warnings left as backlog, not blocking).
- **Added a health check endpoint**, `GET /health` (`server.js`) — reports `{ status, uptimeSeconds, mongo }` without touching auth or the data layer, suitable for a hosting platform's liveness probe.
- **Added graceful shutdown** — `SIGTERM`/`SIGINT` handlers stop the post-publishing scheduler, drain in-flight requests via `server.close()`, and force-exit after a 10s watchdog if something hangs.
- **Added startup config validation** — warns on missing email credentials or a malformed `MONGODB_URI`; refuses to start in `NODE_ENV=production` with no `ADMIN_PASSWORD` set (the alternative is a fresh random password generated and only logged to stdout on every restart).

### Accessibility (WCAG 2 AA)

Audited every page with `@axe-core/playwright` (`wcag2a`/`wcag2aa` rule set). Found and fixed real, concrete violations — not just linted markup:

- **Sitewide color-contrast failures.** The brand teal accent (`#00A3A3` on white, 3.1:1) and a `text-gray-500` utility (`#94a3b8` on white, 2.56:1) both failed the required 4.5:1 for normal text; darkened both. A previous attempt at fixing the project tech-tag pills (the code literally had a comment reading `/* WCAG fix */`) made contrast *worse* (1.39:1, light cyan text on a near-white translucent background) — replaced with solid teal background + white text.
- **Root-caused a sitewide footer-contrast bug**: every footer element carried both a `site-footer` class (correct light-on-dark color) and a `text-gray-600` utility class (dark-on-light color) — the utility class won the cascade tie-break by source order, silently overriding the intended footer color on all 15 page templates. Removed the conflicting class everywhere.
- **Fixed a second instance of the same bug class**: the hidden admin-login button gets appended directly into the footer by `public/inline-editor.js` at runtime, but its own stylesheet (`inline-editor.css`) hardcoded a color meant for light backgrounds — invisible-ish at 3.68:1 against the dark footer.
- **Fixed `link-in-text-block` violations** (links distinguishable by color alone) on `/projects` — and in the process found the underline was never actually applying: `hover:underline` had zero matching CSS rule anywhere in the stylesheet. Made these links always-underlined, fixing both issues in one change.
- **Fixed an `aria-hidden-focus` violation** in the photography lightbox: the closed dialog was `aria-hidden="true"` but its close/prev/next buttons had no `tabindex="-1"`, so they stayed in the page's keyboard tab order while invisible (`opacity: 0; pointer-events: none` — not `display: none`). Now toggles `tabindex` in sync with `aria-hidden` and moves focus into the dialog on open.
- **Fixed Connect 4's dark-themed decorative text** rendering directly on the page's white background instead of the dark surface it was designed for (`.c4-hero p`, `.c4-first-move-label`, `.c4-legend-item`) — and separately, text inside genuinely dark/translucent surfaces (`.c4-toggle-btn`, `.c4-tip`) that was too dark for its own container.
- **Result:** 0 axe violations across all 8 scanned pages (home, about, blog, projects, challenges, contact, photography, connect4), re-verified after every fix rather than assumed.
